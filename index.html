why kn9t?

Most coding agents optimize for convenience.
kn9t optimizes for knowing what happened.
The goal was an agent you reshape in minutes — and making every part replaceable is what made the core auditable.

getting started

Get running in 60 seconds.

# 1 · get it (rust 1.98+)
$ git clone https://github.com/96Ems/kn9t && cd kn9t
$ cargo build --release

# 2 · run it — first launch writes ~/.kn9t and starts the server
$ ./target/release/kn9t

# 3 · type a prompt in the box. that was your first kn9t.
no telemetry loopback-only · Origin-rejected · token-gated (tested with a stolen token) providers, models, plugins → CONFIG.md ↗ write your own → kn9t-plugins ↗

the honest limits

What it isn't.

  • Pre-1.0 — expect sharp edges and schema churn.
  • No magic sandbox — tools run with your privileges; install kn9t-policy first.
  • You bring the model — an API key or a subscription endpoint.
  • Local-first — one user, one machine. No cloud, no accounts.
